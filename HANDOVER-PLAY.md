### The "failed to strip debug symbols" error, and its real cause

The first two builds died with *"Release app bundle failed to strip debug
symbols from native libraries"* and exit code 1. **The libraries were stripped
the whole time.** Flutter's check, in
`packages/flutter_tools/lib/src/android/gradle.dart`
(`_isAabStrippedOfDebugSymbols`), shells out to **`apkanalyzer`** — and
returns `false`, not "unknown", when it cannot find it. `apkanalyzer` lives in
the Android SDK's `cmdline-tools`, which was **not installed**; `flutter
doctor` was reporting exactly that. So Flutter could not verify the strip and
treated that as a failure.

Fixed by installing the command-line tools:

```bash
curl -L -o ct.zip https://dl.google.com/android/repository/commandlinetools-mac_x86_64-16111833_latest.zip
unzip ct.zip                      # yields a cmdline-tools/ folder
mv cmdline-tools "$HOME/Library/Android/sdk/cmdline-tools/latest"
```

(x86_64 because this Mac is Intel; there is an `mac_arm64` build too. It needs
a JDK on `JAVA_HOME` to run standalone — Android Studio's is at
`/Applications/Android Studio.app/Contents/jbr/Contents/Home` — but Flutter
passes its own Java environment, so the build does not need that set.)

After that, `./tool/build_release.sh` runs clean: *"✓ Built
build/app/outputs/bundle/release/app-release.aab (46.2MB)"* plus the signing
summary. **Do not chase the NDK over this.** Gradle auto-installed NDK
25.1.8937393 and CMake 3.22.1 along the way, and `llvm-objcopy` was fine all
along; the NDK was never the problem.

### The one real cost: minSdk 23 → 24

Flutter 3.38's `min_sdk_version_migration` rewrote `android/app/build.gradle`
by itself:

```diff
-        minSdk = 23
+        minSdkVersion = flutter.minSdkVersion
```

`flutter.minSdkVersion` is **24** in 3.38
(`packages/flutter_tools/gradle/src/main/kotlin/FlutterExtension.kt:26`), so
**Android 6.0 (API 23) devices are dropped**. This is not optional and should
not be reverted: the 3.38 engine requires API 24, so a bundle claiming 23
would crash there. The only way to keep API 23 is to stay on Flutter 3.24,
which means Billing Library 7 and a rejected upload. Mention it to the user if
it comes up; it is a real, user-visible consequence of the upgrade.

## 2. The toolchain trap — read this before touching Flutter

**This Mac is macOS 13.7.8 on Intel (x86_64).** Dart raised its minimum macOS
to 14.0 partway through, so most current Flutter releases **cannot start at
all** here. Verified by downloading each Dart SDK and reading `otool -l`:

| Dart | Flutter | min macOS | runs here? |
| --- | --- | --- | --- |
| 3.10.9 | 3.38.x | 10.14 | **yes** |
| 3.11.5 | 3.41.x | 14.0 | no |
| 3.12.0 | 3.44.x | 14.0 | no |
| 3.13.x | 3.47.x | 14.0 | no |

So **Flutter 3.38.10 is the ceiling on this machine**, and it is what the SDK
at `/Users/mac/development/flutter` is pinned to right now (branch `stable`,
hard-reset to tag `3.38.10`, Dart 3.10.9). It was on 3.24.5 before this work.

**Do NOT run `flutter upgrade`.** It pulls 3.47.9, whose Dart VM dies with
`VM initialization failed: Current Mac OS X version 13.0 is lower than minimum
supported version 14.0`, and Flutter becomes unusable for every project on the
machine. If that happens anyway, this is the repair:

```bash
cd /Users/mac/development/flutter
git reset --hard 3.38.10
rm -rf bin/cache/dart-sdk bin/cache/flutter_tools.snapshot \
       bin/cache/flutter_tools.stamp bin/cache/engine-dart-sdk.stamp \
       bin/cache/flutter.version.json
flutter --version          # re-bootstraps, downloads the right Dart SDK
flutter precache --android
```

`flutter` is not on the default PATH in this environment. Prefix commands with:
`export PATH="/Users/mac/development/flutter/bin:$PATH"`.

Other apps on this machine (Sudoku Pulse, Memory Match, TinyGenius Hub) share
this SDK, so a broken Flutter breaks them too.

## 6. Things already checked, so nobody re-does them

- **`targetSdk`/`compileSdk` are 36** — Play's requirement for new apps since
  2026-08-31. Nothing to do.
- **The NDK warning is advisory.** The build warns that plugins want NDK
  27.0.12077973 while `android/app/build.gradle` pins 25.1.8937393. Every
  64-bit `.so` in the bundle already has a LOAD `p_align` of 0x4000 or
  0x10000, so Play's 16 KB page-size rule is already met. No NDK is installed
  on this Mac and none is needed. **Do not bump it to silence the warning.**
  The check:
  ```bash
  python3 -I -c "
  import struct,glob
  for p in sorted(glob.glob('base/lib/*/*.so')):
      d=open(p,'rb').read()
      if d[4]!=2: continue
      off,size,num=struct.unpack_from('<Q',d,0x20)[0],struct.unpack_from('<H',d,0x36)[0],struct.unpack_from('<H',d,0x38)[0]
      a=[struct.unpack_from('<Q',d,off+i*size+0x30)[0] for i in range(num)
         if struct.unpack_from('<I',d,off+i*size)[0]==1]
      print(p, [hex(x) for x in a], 'OK' if max(a)>=16384 else 'TOO SMALL')"
  ```
- **The App Store side is finished except the Submit button.** Build 13 is
  uploaded, the version page reports no errors, "Add for Review" is enabled.
  The user presses it.
- **`google_mobile_ads` is pinned at exactly 4.0.0.** Latest is 9.2.0. It was
  left alone on purpose — bumping it is a separate, large job and it already
  compiles against recent stable Flutter (Codemagic builds iOS that way).
